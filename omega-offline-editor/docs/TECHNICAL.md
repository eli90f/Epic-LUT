# Technical notes and current-game validation

Native Win32/GDI C++17 frontend, static MSVC runtime. Embedded icon and debug LUT; no companion runtime DLL is required. Disk archive catalog resolves current texture IDs from native archives and DSAR/DSAA containers, applies resource precedence, validates offsets and decompresses bounded chunks. Only RGBA16F/RGBA32F material LUTs (23 × 1–64) and pattern LUTs (3 × 1) are accepted. Other formats/dimensions are reported as unsupported rather than converted silently.

The editor holds independent current and original float32 RGBA arrays and source metadata. DDS16F is decoded exactly to float32; DDS output uses RGBA32F. Presets include original/current arrays, source identity, native 340-byte header and a checksum. Save publication uses temporary files and replacement safeguards. Patch writing ports the original Epic static exporter; synthetic DDS and all three patch files match the original Lua writer byte for byte. It preserves native identity fields and deliberately emits one unstreamed RGBA32F mip, following the upstream exporter. This is an explicit storage conversion, not preservation of original DDS compression or mip structure.

Current installed game read-only validation (2026-10-24): 3,538 archive/patch files, 17,232 unique texture resources, 2,509 supported LUTs; 14,531 other-format and 192 other-dimension resources excluded. The current 9ba626afa44a3aa3 base exists and has archive magic 0xf0000011. Real resource 0006bd52b87c7d95 in d451ab9c17f64b19 is 23×8 RGBA16F. Native-header preservation, DDS export/reload and edited patch export/reload all passed exact pixel/resource checks. Large raw DSAR chunks are accessed through validated small ranges, accommodating current files without reading unrelated chunks in full.

No historical runtime addresses or pointers are reused. Current serialized unit/material reference tables are validated before naming owners. This validates serialized texture replacement structure, not live bindings, gameplay compatibility, anti-cheat compatibility or actual visual output. Real game installation was not modified during automated validation. Evidence is retained under project/build/current-game-assets-proof.json and the backend test sources under tests/.

The renderer uses recovered column semantics and qualitative material approximations; its display tone mapping does not mutate the source values. Unknown columns retain their raw values. See PREVIEW-LIMITS.md for visual omissions.

Owner-name extension: 455 named supported LUTs, 309 weapon/equipment, 42 vehicle and 107 armor/helmet links (categories overlap), proven against the current serialized unit/material graph. Exact examples and licensing provenance are in ASSET-NAME-PROVENANCE.md. Real named gun and vehicle patch write/readback tests passed without writing to game files. Current evidence: current-owner-graph-proof.json.

Original EPIC-LUT v2 TSV preset import is data-only and bounded. Native parser results match the original Epic Lua decoder, including multi-LUT float buffers and parsed metadata. GUI import rebinds by exact current resource ID plus dimensions; it takes current baseline/header provenance and applies imported RGBA values. Upstream runtime activation/gear selection flags are not implemented. RGB-only v1, cape16 LUTs and outfit ZIPs are explicitly unsupported. OMEGA save/export currently operates on one selected LUT.


## R5.9.3.3 frontend and installation

The startup message starts an asynchronous disk scan. Identified resources sort ahead of unknown resources. Simple mode expands the item list and hides raw tools; Advanced retains the exact same underlying document and field edits. A per-resource staged-document map preserves edits while navigating. Explicit preset loads bypass that map so an older staged document cannot replace an intentionally loaded preset. Restore clears staged state and reloads current files.

Install emits one original-format patch triplet per staged resource into vacant numeric patch slots above existing layers. Original game archives and unowned patches are not overwritten. A canonical-game-directory-keyed ledger in State stores SHA256 proofs plus native baseline presets. Installed documents reopen with their original baseline and edited pixels. Install validates all owned-file proofs, releases cached archive file handles, temporarily removes old owned patches, rescans the remaining current baseline, validates targets and publishes the new owned set. Handled failures roll back the previous owned files and ledger. Restore verifies proofs before deleting only owned triplets. Process-name enumeration checks that helldivers2.exe is closed; no process-memory access is used.

Installer fixture tests passed for two-LUT installation, existing unowned slots, startup state reload, scan/load/reinstall with cached handles, stale-source rejection, a forced manifest publication failure with rollback, changed-owned-file refusal, and restore preserving original archives and unowned patches. These checks validate handled operation failures, not power-loss recovery or actual in-game rendering. Native bcrypt provides SHA256 and is a standard Windows component.

UI checks verified automatic loading of 2,509 records and the Advanced dropdown's spacing below the Back button. The R5.9.3.3 EXE was built using MSVC64 C++17 /O2 /MT and launched successfully.
